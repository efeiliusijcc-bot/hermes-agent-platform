# 开发规范

## 1. 架构边界

1. `docs/hermes_agent_offline_platform_detailed_design.md` 是唯一架构依据。
2. 严格按 Phase 0 至 Phase 9 顺序开发，不跨阶段提前实现。
3. 若出现架构冲突、设计缺陷或环境限制，记录问题、影响和建议，确认后再改变方向。

## 2. 代码规范

- 模块职责单一，跨模块依赖通过明确接口完成。
- 配置必须外置，禁止写死环境地址、绝对路径、密码或 API Key。
- 所有外部调用必须设置超时并提供可诊断的错误日志。
- 日志不得记录密码、令牌、模型密钥或原始连接串。
- 运行时权限以 Agent 绑定关系为准，默认拒绝未绑定能力。

## 3. 测试规范

每个阶段至少包含：

1. 自动化测试。
2. 与阶段目标对应的人工可验证步骤。
3. 116 节点上的 Compose 或端到端验证（适用时）。
4. 失败场景和权限边界验证（适用时）。

本机不运行 Docker。Docker 与 Compose 命令只在 116 测试节点执行，并始终显式指定：

```bash
docker compose -p hermes-agent-platform ...
```

## 4. Git 规范

- 每个 Phase 单独提交。
- 新功能使用 `feat:`，修复使用 `fix:`，测试使用 `test:`。
- 提交前执行自动化测试、`git diff --check` 并检查暂存范围。
- 不在一次提交中混入下一阶段内容。

## 5. 116 节点安全边界

- 项目目录：`/opt/hermes-agent-platform`。
- Compose 项目名：`hermes-agent-platform`。
- 禁止复用现有容器名、网络名、卷名和宿主机端口。
- 禁止停止、重启、删除或重建非本项目容器。
- 部署前后都要记录本项目容器、网络、卷和端口状态。

## 6. 离线部署规范

- 依赖版本必须锁定。
- 镜像和发布包必须生成 SHA-256 校验值。
- 离线包必须包含镜像、Compose 配置、环境变量模板、迁移脚本和操作文档。
- 导入验证不得访问公网；模型通过内网 `MODEL_ENDPOINT` 调用。
